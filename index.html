Hybrid encryption, entirely in your browser

Lock a message the way real systems do.

Your message is sealed with a fast AES-256 key. That key is then wrapped in RSA-2048 so only the holder of the matching private key can ever unlock it. Nothing here touches a server — every operation runs on the Web Crypto API, on this device, right now.

Recipient keypair

A 2048-bit RSA keypair is generated on load and stored only in this browser (localStorage). The public key wraps the AES key when encrypting; the private key unwraps it when decrypting. This mirrors the outline — key exchange handled by RSA — without needing any backend.

What's actually happening

  1. Generate: the browser creates a random AES-256 key and a random IV — used once, for this message only.
  2. Seal the message: AES-GCM encrypts the plaintext with that key, producing ciphertext plus an authentication tag baked in.
  3. Wrap the key: the AES key itself is encrypted with the recipient's RSA public key, so it can travel alongside the ciphertext without exposing it.
  4. Unwrap and open: the recipient's RSA private key recovers the AES key, which then decrypts the ciphertext back to plaintext.
